## 1. 先更正一处算术

制作人给出的估算是「退出首页的时点从约 **98** 次变成约 **93** 次」。
按 `W_MIN = 0.05 × W0`、纯 `γⁿ`、`γ = 0.97` 实算：

| 口径 | 实算 | 制作人估算 | 差异 |
|---|---|---|---|
| `0.97⁴⁰` | **0.2957** | ≈0.30 | ✅ 一致 |
| 无制动退场时的 `n` | **99** | ≈98 | 取整差一，可忽略 |
| `brakeFactor = 0.80` 退场时的 `n` | **92** | ≈93 | ⚠️ 实际是 92 |
| **差值** | **7 次** | 5 次 | 🔴 **实际比估算多 2 次** |

方向与结论都不变，但差值应记为 **7 次**。已配用例
（`BrakeMetricsTest.theSeedBrakeIsWorthAboutSevenDeliveries`）钉住这两个数。

## 2. 闭式：一档制动到底值多少次投放

制动是乘性的、`γⁿ` 是指数的，所以「制动值多少次投放」有闭式解，
**与 `W0`、与退场线取值都无关**：

```
制动 b 的代价 = ln(1/b) / ln(1/γ)   次投放
              = ln(1/b) / 0.030459  （γ = 0.97）
```

时间维同理有闭式解。`T_eff` 在 >72h 段是 `e^(-(a-72)/τ₂)`，τ₂ = 36h，
所以「制动 b 相当于把这张卡凭空催老多少小时」是：

```
制动 b 的代价 = τ₂ × ln(1/b)   小时
              = 36 × ln(1/b)   （τ₂ = 36h）
```

两个式子都**与 `W0`、与退场线取值无关**——换句话说，
调 `W0` 或调退场线都不会改变这张代价表，它只依赖 `γ` 和 `τ₂`。

### 2.1 定稿表逐格代价

🔴 **这一节是给运营看的。** 调表的人在界面上只看得到一个小数，
看不出它意味着少推多少——这张表就是那个翻译。

`B1` 判的是「没人喜欢」，那不是过错，不该判死刑；判死刑的是 `B3`（见 §6）。

两维单调性由 `BrakeTable#validate` 在启动时校验，见 §5。

## 3. 制作人的直觉是对的：算进时间衰减后寿命更短

制作人自己指出「没有算进 `T_eff` 的时间衰减，真实寿命应该更短」。核实：**确实如此，而且是决定性的。**

单看时间衰减（`n = 0`，即完全没被投过）：

```
T(a) < 0.05  ⟺  a > 143.9 小时 ≈ 6.0 天
```

也就是说 **一张卡即使一次都没被投过，6 天后也会因为时间衰减自己跌破退场线。**
要让 `n` 成为约束条件，这张卡得在 6 天内攒够约 99 次去重曝光。

所以在多数情况下，**先把卡压下去的是时间，不是投放次数**。

同一个制动在时间维上的代价同样有闭式：

```
制动 b 的代价 = τ₂ × ln(1/b)   小时   （τ₂ = 36h，快衰段）
```

| `brakeFactor` | 时间维代价 | 投放维代价 |
|---|---|---|
| 0.80 | **8.0 小时** | 7.3 次 |
| 0.70 | 12.8 小时 | 11.7 次 |
| 0.60 | 18.4 小时 | 16.8 次 |

实算：无制动 143.9h 退场，`brakeFactor = 0.80` 时 135.8h 退场，**差 8.0 小时**——
在一条约 6 天的寿命上砍掉 8 小时，约 **5.6%**。

🔴 **两个维度给出的结论一致：这组种子数值下，刹车的效果在 5%–7% 量级。**

## 4. 所以这组数是初值，不是结论

上面三节合起来说的是同一件事：**当前的刹车接近装饰。**

这是**刻意选的**，不是疏漏——先把可配的机制立起来、拿这组数当初值，
等真实拒绝率分布出来再调。真正重要的是：**调的时候要有依据。**

### 依据就是这个指标

`BrakeMetrics` 报三个数：

- 被刹车的卡，平均还能被投多少次
- 未被刹车的卡，平均还能被投多少次
- **两者之差**（以及相对差）

🔴 **两个数字如果长期贴在一起，就说明刹车是装饰。** 那时该做的是调表
（`ECHO_BRAKE_TABLE`），而不是把这个指标从看板上摘掉。

⚠️ **不要用「有多少卡被踩了刹车」替代这个指标。** 有多少卡被刹车，
和踩下去之后有没有区别，是两个问题；前者好看得多，也没有用。

---

## 5. 调表时要守住的两件事

1. **两个维度都必须单调不增。** `BrakeTable` 在构造时校验，不满足直接启动失败。
   理由是这张表可配，而可配的表迟早会被填成非单调的——那时
   「情况更糟时惩罚更轻」，而且**在报表上看不出来**。
2. **格子值必须落在 (0, 1]。** 大于 1 就是把刹车踩成油门，
   `W = W0 × γⁿ × T_eff × brakeFactor` 的「除 `W0` 外全部因子恒 ≤1」这条代数红线当场失效。

## 6. 一条不要误读的分界

`B1` 拒绝率 ≥20% 的「立即终止」**已取消**，20% 与 33% 现在只是表里的两列。

⚠️ 这**不**意味着举报没有后果：

| | `B1` 降档 | `B3` 终止 |
|---|---|---|
| 管什么 | 很多人划走 —— **口味问题** | 这东西不该在这儿 —— **合规问题** |
| 谁判 | 分发侧按拒绝率自动判 | 审核链路人工判 |
| 后果 | 推得少一点，仍在流里 | 退出全部主动分发（转 `RESTRICTED`） |

举报确实计入 `B1` 的拒绝率分子，但那只是「有人不想看」的一种表达；
**举报能不能把内容拿下，由审核判，不由分发判。**
